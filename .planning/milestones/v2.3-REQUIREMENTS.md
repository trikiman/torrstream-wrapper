# Requirements (Archived): TorrStream v2.3 Lampa parser shim

**Defined:** 2026-05-22
**Shipped:** 2026-05-22

Source: 2026-05-17 user-blocking incident — plain `http://jac.red` blocked on
user's ISP; manual switch to `https://jac.red` worked but was fragile.

## Lampa shim

- [x] **LAMPA-01**: `GET /api/v1.0/torrents` on TorrStream proxies to `JACRED_URL/api/v1.0/torrents`, forwarding all query params and returning the raw upstream response body (flat array of jacred records). Lampa with `parser_torrent_type=jacred` parses it natively.
- [x] **LAMPA-02**: `/api/v1.0/torrents` and (added mid-phase) `/api/v2.0/indexers/all/results` include `Access-Control-Allow-Origin: *` so a Lampa client running on `lampa.mx` can fetch cross-origin without preflight failure.

## Mid-phase amendment

- [x] **LAMPA-01b** (added 2026-05-22 during deploy verification): `GET /api/v2.0/indexers/all/results` proxies to the same upstream — required because Lampa's `parser_torrent_type=jackett` (the user's actual setting) hits the Jackett REST URL pattern, not jacred's v1.0 path. jacred mirrors transparently support both paths and return Jackett-shape `{Results:[...]}` for the v2.0 path; we proxy each route to its matching upstream path.

## Source incident

Captured 2026-05-17 in chat: user shared screenshot of Lampa "Парсер не отвечает на запрос (http://jac.red)". Earlier same-day fix was switching Lampa's stored `jackett_url` from `jacred.xyz` to `https://jac.red` — worked but fragile. v2.3 makes the wrapper itself the stable parser entry point.
